# Core patches

Towelwise AI changes Code-OSS through its built-in extension first, and patches core only where the extension cannot reach ([decision 0005](../../docs/decisions/0005-patch-core-only-when-the-extension-cannot.md)). `ide/build.sh` copies every `*.patch` here into the VSCodium checkout's `patches/user/`, which VSCodium applies after its own patches. Patches are plain `git apply` diffs against the pinned upstream source. On every pull request that touches `ide/`, CI (`.github/workflows/core-patches.yml`) applies them after VSCodium's own patches and fails if they do not apply or add a type error; building and running the app stays a manual check.

Each patch has a note below: why it exists, what it touches, and how it fared at each upstream update (the upkeep record 0005 asks for).

## 0001 menu hook (`0001-towelwise-menu-hook.patch`)

**Why.** The owner wants the option to hide built-in features (the integrated terminal, Tasks, Debug, Testing, Notebooks) and have a Towelwise menu of its own, without a new patch for each change. Spec: [menu-hook.md](../../.work/specs/menu-hook.md).

**What it does.** Two settings that the built-in extension ships are the whole interface: `towelwise.menus.hidden` (command ids or `prefix.*` patterns to hide) and `towelwise.menus.towelwise` (the entries of a new Towelwise menu). A hidden command is not offered in menus, the Command Palette or default shortcuts, but still runs when called by other code. An entry of the form `menu:MenuId` hides the submenu item that opens that menu (used for the View menu's Appearance and Editor Layout), never the commands inside it; it matches the menu id exactly. Spec: [view-menu.md](../../.work/specs/view-menu.md). The pinned source registers those two submenus only on the View menu, so no other menu loses them.

**What it touches (6 files, one hunk or new file each; +271/-2 lines).**

- new `platform/commands/common/hiddenCommands.ts`: the shared list, its matcher, and a startup default equal to the setting's default so nothing flashes before the setting is read. It also holds `isMenuHidden`; the command matcher skips `menu:` entries so a command that happens to share a menu id is not hidden.
- `platform/actions/common/actions.ts`: `MenuRegistry.getMenuItems` returns its result without hidden commands, after the implicit Command Palette items are added, and drops hidden alternate actions; menus rebuild when the list changes. A submenu item whose menu id is listed as `menu:MenuId` is dropped there too (+2 lines, view-menu slice). The startup default and the setting's default are both empty (decided 2026-11-03): every built-in menu shows unless the person lists it. Earlier versions hid Terminal, Tasks, Debug, Testing and Notebooks by default.
- `platform/keybinding/common/keybindingsRegistry.ts`: default shortcuts of hidden commands are left out (removal rules and user shortcuts are untouched).
- `workbench/services/keybinding/browser/keybindingService.ts`: rebuilds the resolver when the list changes.
- new `workbench/contrib/towelwise/browser/towelwise.contribution.ts`: reads both settings, applies the list and builds the Towelwise menu. Entries keep the array order, and a group name that comes back after another group is a new section (counted by runs). The top-level Towelwise item is registered after its entries, and again on every rebuild and whenever a context key that one of the entries' conditions reads changes: the menu bar redraws only when its main menu changes, not when a submenu gains entries, and it drops a submenu with nothing to show without watching the conditions of entries inside it. The settings are also read again once extensions have registered, because on a first launch the contribution runs before the built-in extension's settings exist.
- `workbench/workbench.common.main.ts`: one import, added at the end of the imports, away from the block VSCodium edits.

**Known limits.** Editor actions that the Command Palette reads straight from the active editor are not covered. Typing `term ` in quick open still opens the terminal picker. The built-in JavaScript Debug extension adds its own terminal command.

## 0002 welcome header (`0002-towelwise-welcome-header.patch`)

**Why.** The Welcome page showed VSCodium's subtitle "Editing evolved" and no mark. The subtitle is a string in core code, so an extension cannot change it. The owner chose "Coding Gone Hyper", a nod to Hyperspace mode (a first idea that quoted a film was dropped to stay clear of a studio's property).

**What it touches (2 files, one hunk each; +12/-1 lines).** `welcomeGettingStarted/browser/gettingStarted.ts`: the subtitle text. `welcomeGettingStarted/browser/media/gettingStarted.css`: a `::before` rule that draws the Towelwise mark before the product name. The mark itself is a file overlay, not part of the patch: `ide/build.sh` copies `ide/icons/code-icon.svg` to `towelwise-mark.svg` beside that stylesheet. The faint mark in an empty editor is likewise a file overlay (`ide/icons/letterpress/*.svg` over the four `letterpress-*.svg` files).

**Known limits.** The subtitle keeps its original localization key, so a translated build would still show the translation of "Editing evolved"; Towelwise ships in English only for now. VSCodium already edits `gettingStarted.ts`; this patch is made against the file as VSCodium leaves it and applies after theirs.

## 0003 layout bridge (`0003-towelwise-layout-bridge.patch`)

**Why.** Setting the widths and heights of the side bars and panel needs the layout service, which no extension API reaches ([decision 0003](../../docs/decisions/0003-hyperspace-never-reads-or-reopens-layout-state.md), [0005](../../docs/decisions/0005-patch-core-only-when-the-extension-cannot.md)). Spec: [phase-4-sizes.md](../../.work/specs/phase-4-sizes.md).

**What it does.** Seven internal commands, a bridge with no feature logic. `_towelwise.layout.state` returns, for the main window it was called from, each part's visibility and size in pixels (`sidebar`, `auxiliarybar`, `panel`), the panel's position and the window's size. Each visible part also carries its active container, `container: { id, title }`, when it can be named (the picker shows these as area names; spec: [phase-4-area-names.md](../../.work/specs/phase-4-area-names.md)). `_towelwise.layout.setSize(part, pixels)` sets one part along its one sizing dimension (the panel's by its position) and returns the size the grid ended up with. `_towelwise.layout.locate(containerId)` says where a view container lives now (`sidebar`, `auxiliarybar` or `panel`), or nothing if the window has no such container. `_towelwise.layout.moveContainer(containerId, location)` moves a container to one of those areas, the call that dragging its icon makes, and returns false if it does not exist or cannot move (added 2026-11-03 for My layout, [spec](../../.work/specs/phase-4-my-layout.md), under the amendment to [0005](../../docs/decisions/0005-patch-core-only-when-the-extension-cannot.md)). `_towelwise.layout.mainGroupCount` returns the main window's editor group count, `_towelwise.layout.mainLayout` returns the main window's editor grid in the shape of `vscode.getEditorLayout` (which answers for the active window; added 2026-11-05 so drift checks can read the main grid while a floating window is open), and `_towelwise.layout.focusMain` brings the main window to the front and returns true once its editor part is the active one (added 2026-11-04, [spec](../../.work/specs/phase-4-main-window-groups.md)): the extension API cannot tell which window a group is in, and setting the grid, focusing groups and moving tabs act on the active editor window. The leading underscore keeps them out of the palette; it is not an access boundary (any extension can already resize these parts with the built-in increase and decrease commands).

**What it touches (2 files; +117 lines).** New `workbench/contrib/towelwise/browser/layoutBridge.contribution.ts`, and one import added in `workbench/workbench.common.main.ts` after the one from 0001, so it applies only after 0001.

**Known limits.** Whether the grid gives exactly the requested size is checked in the built app.

## 0004 hide the video walkthrough (`0004-towelwise-hide-video-walkthrough.patch`)

**Why.** Code-OSS's built-in "Get started with Towelwise AI" walkthrough (id `Setup`) has one step, "Watch video tutorials", which promises "Towelwise AI's key features" but opens Microsoft's VS Code videos. The owner asked to remove it (2026-11-05). Built-in walkthroughs are core content that an extension cannot hide.

**What it touches (1 file, two hunks; +2/-2 lines).** `welcomeGettingStarted/common/gettingStartedContent.ts`: the `Setup` walkthrough's `when` becomes `'false'`, which hides it from the Welcome page, its featured slot and "Welcome: Open Walkthrough…". It is hidden rather than deleted so the patch stays small against upstream edits. The accessibility walkthrough (`SetupAccessibility`, shown only in accessibility mode) loses its `next: 'Setup'`: the page lists walkthroughs without checking `when`, so its "Next Section" button would still have opened the hidden one (Codex review, 2026-11-05).

**Known limits.** The accessibility walkthrough no longer has a "Next Section" button. Anything else that opens `Setup` by id (a link or command naming it) would still show it; none was found in the pinned core. Our own "Get Started with Towelwise" walkthrough is untouched.

## Dropped: hiding the Terminal tab (an earlier patch, also numbered `0002`)

The first version had a second patch giving the Terminal view in the bottom panel a `when` that went false while Toggle Terminal was hidden, so the tab disappeared. Review of the pinned source (2026-11-02) showed that a view whose `when` is false is inactive, and `ViewsService.openView` returns nothing for an inactive view, so a terminal created in the bottom panel by an extension (`MainThreadTerminalService.$show` to `TerminalGroupService.showPanel`) could no longer be shown. Terminals in the editor area (such as Claude Code's terminal mode) were not affected, but the panel case could not be accepted. The spec's criterion 8 allowed this fallback, so the patch was dropped and the Terminal tab stays. Anyone who wants it gone can hide it from the panel's tab menu. Deleting a file from `ide/patches/` is all it took: the build copies whatever is there.
